# Language domain (i18n)

Which language the UI speaks, how that choice is remembered, and how it
follows a user from one browser to another. Start with the overview, then
open the detail that matches the code you are touching.

English is the default and the fallback (subject requirement). The same
flows are also drawn as one poster in
[`i18n-language.png`](i18n-language.png) (Excalidraw source next to it).

Decision: react-i18next, recorded in HYP-56. No ADR: nothing here is a
structural choice beyond the library.

## 1. Which language wins (HYP-56)

Two moments, two sets of information. At page load nothing is known about
the account, so the language comes from what the browser holds. Once
`GET /users/me` answers, the account language takes over. Logging out
puts the first rule back.

```mermaid
flowchart TD
    start(["page load"]) --> s1{"hypertube_language<br/>in localStorage?"}
    s1 -- "yes" --> use1["use it"]
    s1 -- "no" --> s2{"navigator.languages has a<br/>supported language?<br/>(fr-CA gives fr)"}
    s2 -- "yes" --> use2["use it"]
    s2 -- "no" --> use3["English"]

    use1 --> render["first render in that language"]
    use2 --> render
    use3 --> render

    render --> auth{"logged in?"}
    auth -- "yes, /users/me answered" --> acct["switch to<br/>user.preferredLanguage"]
    auth -- "no" --> stay["keep the language"]
```

Priority at login: account language, then manual choice, then browser,
then English. The starting language is resolved in `lib/i18n.ts` before
the first render, so there is no flash of English; the account language
arrives later, in `useLanguageSync`.

## 2. Switching language (HYP-56, HYP-106)

```mermaid
sequenceDiagram
    actor U as User
    participant S as SPA (LanguageSwitcher)
    participant L as localStorage
    participant A as API

    U->>S: picks "Francais"
    S->>S: i18n.changeLanguage (UI changes at once)
    S->>L: hypertube_language = fr
    alt logged in
        S->>A: PATCH /users/:id { preferredLanguage: fr }
        alt 200
            A-->>S: the saved profile
            S->>S: updateUser (the in-memory user follows)
        else 401
            A-->>S: 401
            Note over S: left to the session-expired net, no message here
        else any other failure
            A-->>S: 4xx / 5xx / network
            S->>U: "Not saved to your account" under the picker (role=status)
        end
    end
```

A failed `PATCH` keeps the new language on screen, since the visitor chose
it, but says it is not on the account: another device or the next login
would bring the old one back (HYP-106). The message clears on the next
switch.

## 3. Registration (HYP-56)

The register page sends the language the visitor is browsing in. Without
it a new account is saved as `en`, and the account language wins at login,
so a French visitor would be flipped back to English on their first login.

```mermaid
sequenceDiagram
    actor U as Visitor
    participant S as SPA (register page)
    participant A as API

    U->>S: submits the form (UI in French)
    S->>A: POST /users { ..., preferredLanguage: fr }
    A-->>S: 201
    S->>U: redirect to /login
```
